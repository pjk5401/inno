# Ubuntu VM 운영 안내

## 최초 설치

1. GitHub 저장소를 clone하고 프로젝트 루트에서 `bash manage.sh` 실행.
2. 1번 환경 점검. 기존 프로젝트가 80포트를 사용하면 먼저 운영자가 포트를 조정해야 한다. 스크립트는 다른 서비스를 중지하지 않는다.
3. 필요할 때만 2번 인프라 설치. 기존 Docker/Compose가 있으면 재사용. Docker만 있고 Compose가 없으면 기존 설치 방식을 보존하기 위해 안내 후 중단한다.
4. 3번 최초 설정. 기본 주소 `https://inno-pjk5401.apps.dauai.org`. 프록시 정제/원본 접근 제한을 확인하지 않았다면 헤더 신뢰는 기본 0.
5. 운영/테스트 DB를 생성·마이그레이션한 후 양쪽의 초기 관리자를 설정한다. 비밀번호는 숨겨 입력하며 10자 이상과 Django 검증을 적용한다.
6. 4번 운영 실행. 13번 테스트 실행. 테스트 실행 메뉴는 운영 Nginx도 준비한다.
7. 브라우저에서 로그인. 운영 인정 위치를 설정하고 수업·명단을 등록한다. 테스트는 별도 로그인 후 기본 테스트 준비.

최초 설정이 중간에 실패해도 비밀값 파일은 다시 생성하지 않는다. 4번 실행으로 DB 준비를 마친 뒤 11번으로 관리자 계정을 설정하면 재개할 수 있다.

## 저장 경로와 백업

`/var/lib/attendance/postgres`, `signatures/live`, `signatures/test`, `config/runtime.env`, `backups`를 사용한다. 앱 UID 10001에 서명 쓰기 권한을 부여한다. 운영 DB 포트는 호스트에 공개하지 않는다.

백업은 운영/테스트 앱을 잠시 정지해 진행 중 쓰기를 마친 뒤 DB dump 두 개, 서명 디렉터리, 설정, 소스 커밋을 저장한다. 백업 생성 후 원래 실행 중이던 앱만 다시 실행한다. 출력 파일은 `.tar.gz`와 SHA256 체크섬이며 root만 읽을 수 있다. 학교 스토리지에 자동 외부 전송하지 않는다. 파일 자동 삭제는 없다. 잔여 2GB 미만이면 큰 작업을 중단한다. 애플리케이션 로그는 컨테이너별 10MB × 3으로 제한한다.

**동일 VM 디스크의 백업은 디스크 자체 손상에 대비하지 못한다.** 장기 보관 중 저장 공간은 운영자가 점검해야 한다.

## 업데이트와 복구

실제 접수 중에는 업데이트하지 않는다. 7번은 로컬 변경이 있으면 중단하고, 백업 후 `git pull --ff-only`를 수행한다. 새 DB 마이그레이션 뒤 기존에 실행 중이던 앱을 다시 실행한다. 실패하면 오류를 표시하며 DB 버전이 달라질 수 있으므로 무조건 이전 코드를 자동 실행하지 않는다.

10번 복구는 체크섬·백업 파일 경로를 검증한다. 백업 소스 커밋과 현재 커밋이 다르면 두 버전을 표시하고 CHECKOUT 확인을 받아 소스도 해당 커밋으로 전환한다. 로컬 변경이 있거나 해당 커밋을 찾을 수 없으면 데이터 변경 전에 중단한다. 복구 직전에 현재 상태도 백업한다. DB·서명·설정을 복원하고 DB 계정 비밀번호를 복원한 설정에 맞춰 재설정한다. 성공 후 운영/테스트를 모두 실행하므로 필요하면 테스트를 14번으로 정지한다. 이전 버전 복구 후 소스는 detached HEAD 상태이므로 다시 최신 업데이트를 하려면 원래 브랜치로 돌아가야 한다.

VM 자체를 새로 준비한 경우 인프라/최초 설정을 마친 후 백업 `.tar.gz`와 `.sha256`을 해당 경로로 옮기고, 소스를 백업 커밋으로 맞춘 후 복구한다. 백업에는 비밀값이 있으므로 GitHub에 올리지 않는다.

## 삭제

1단계는 컨테이너·전용 네트워크만 제거. 2단계는 출석 DB·서명·설정 제거(백업 유지). 3단계는 백업까지 제거. 각 단계는 별도의 확인 문구가 필요하다. 고정 경로가 다른 곳으로 연결된 심볼릭 링크이면 삭제를 중단한다. 다른 Docker 프로젝트·전체 Docker 이미지/볼륨을 정리하지 않는다.

## 학교 프록시 확인

- 외부 도메인에서 HTTPS 인증서가 정상이며 모바일 브라우저 위치 권한 요청이 가능한지.
- 학교 서비스 자체의 별도 로그인 게이트가 없는지(학생에게 요구되는 로그인이 없어야 함).
- `/test/` 하위 경로와 POST가 그대로 전달되는지.
- 요청 본문 최대 크기 8MB 이상, 엑셀 출력 대기 시간 약 100초 이상인지.
- X-Forwarded-Proto 헤더를 클라이언트가 위조하지 못하도록 프록시가 정제하는지.
- VM 시각 동기화가 정상인지.

## GitHub에 올릴 때

루트 `.gitignore`를 적용해 소스·문서·Docker·마이그레이션만 올린다. 계정 비밀값과 실제 데이터는 올리지 않는다. `festival-check/`는 초기 중단 템플릿으로 사용하지 않는다. 저장소 주소가 정해진 뒤 평소 Git 절차로 최초 커밋/push한다. 이 구현은 자동으로 원격 저장소를 만들거나 VM에 접속하지 않는다.

## 고정 QR·타 학과 출석 업데이트 (2026-10-25)

소스를 원격 저장소에 반영한 뒤 접수하지 않는 시간에 7번 업데이트한다. 이 메뉴는 백업 후 새 소스를 받고 운영/테스트 모두 마이그레이션한다. 0003은 기존 수업·명단·출석·서명을 보존하고 타 학과 기록 필드·일자/학번 유일 제약을 추가하며 QR 갱신 주기 설정을 제거한다. 데이터 초기화나 재설치는 필요 없다.

담당자 ‘현장 QR’에서 인쇄 또는 PNG 저장한다. 학생 URL은 운영 `/enter/`, 테스트 `/test/enter/`다. QR은 시각·테스트 초기화와 무관하게 유지되며 서버 외부 도메인이 바뀌면 새 주소로 다시 인쇄한다. 테스트 QR이 운영 행사장에 섞이지 않도록 구분한다.

기존 테스트 위치 모드 설정은 업데이트만으로 바꾸지 않는다. 모든 모드에서 실제 좌표 수신이 필수이며 실제 인정 구역을 검증할 때는 위치 모드를 ‘실제 위치’로 선택한다. 이후 전체 테스트 초기화 시에는 ‘실제 위치’가 기본이다. 메뉴 16번 HTTP 부하 시험은 합성 좌표를 사용하고 위치 모드를 ‘모의 구역 안’으로 전환하므로, 휴대폰 현장 시험 전 다시 실제 위치로 돌린다.
