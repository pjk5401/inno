# 구현 검증 결과

검증일: 2026-10-22. Windows 개발 환경에서 수행했다. 사용자의 Ubuntu VM에는 접속하거나 배포하지 않았다.

## 완료한 확인

- 운영 설정에서 Django 자동 테스트 26건 통과.
- 테스트 설정에서 동일 테스트 26건 통과.
- 백업 압축 해제 경로·심볼릭 링크 차단 및 정상 복구/누락 검사 2건 통과.
- 총 자동 테스트 54건 통과.
- Django 시스템 검사 통과, DB 모델과 최초 마이그레이션 일치 확인.
- 정적 파일 수집 성공.
- VM 메뉴·DB 초기화·검증 스크립트의 Bash 문법 검사 통과.
- JavaScript 문법 검사, Python 구문 검사, Compose와 GitHub Actions YAML 읽기 검사 통과.
- 브라우저에서 담당자 로그인 → 테스트 정상 시나리오 준비 → QR 생성 → 로그아웃 → 익명 학생 접속 → 수업/학번/이름 입력 → 마우스 서명 → 제출 → 출석 완료 확인.
- 브라우저 검증에서 발견한 `no-referrer`에 의한 Origin null/CSRF 실패를 `same-origin` 정책으로 수정하고 로그인·출석 성공 재확인.
- HTTP 부하 점검 도구를 로컬에서 가상학생 6명/동시 작업 1개로 시험: 6건 성공, 실패 0건. 도구의 전체 요청 흐름 점검이며 VM 처리량 검증 결과는 아니다.

## 자동 테스트 범위

접수 시작·지각·종료 경계, 5분 만료, 만료·변조·다른 환경 QR, 중복·재전송, 수업·이름 불일치, 위치 경계·오차·오래된 값·비정상 수치, 빈/잘못된 서명, 운영에서 모의 기능 무시, 초기화 후 파일/세션/QR 폐기, 모의 출처 표기, 학생의 개인정보 접근 차단, 조교 시스템 권한 차단, CSRF, 화면 렌더링, 두 종류 Excel 및 학번 0 보존, 명단 미리보기/확정, 수식 입력 차단, 수동 정정 이력·오래된 수정 차단.

## VM에서 남은 검증

개발 PC에는 Docker 엔진이 없어 Docker 이미지 빌드/컨테이너 실행/실제 PostgreSQL 동시성/Ubuntu 설치·백업·복구를 실행하지 못했다. 소스에 PostgreSQL 기반 GitHub Actions 테스트와 별도의 컨테이너 smoke workflow를 포함했으나 원격 저장소에 push하지 않았으므로 이 실행 결과를 주장하지 않는다.

VM에서 1→필요시 2→3→4→13 메뉴를 실행하고 다음을 확인한다.

1. 학교 HTTPS 프록시, 80포트 경로, Secure 쿠키와 로그인.
2. 운영/테스트 DB 접속 권한 격리, 서로 다른 데이터 유지.
3. 아이폰/안드로이드 실제 위치 권한 및 현장 정확도.
4. 16번 메뉴 가상학생 200명 제출 후 출석부 인원·서명·누락 점검.
5. 백업 생성/복구, 재부팅 후 자동 실행, 파일 권한.
6. 동시 운영/테스트 상태에서 메모리·CPU·디스크 점검.

위 항목은 환경 의존 검증이며 사용자 VM 테스트 전에는 운영 준비 완료로 간주하지 않는다.
